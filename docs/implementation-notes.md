# 苹果乐 Windows 桌宠 1.1.1 · 精一走动修正

本轮接入用户以“勉强可以了，继续”确认的精一八帧候选，资源为 `resources/animations/ex1/walk-approved-v2.png`，与验收图集 SHA256 完全一致。保留原先的精一点击动作、其他三种形态和玩偶资源。原候选、八张生成原图、提示词及审核记录保存在 `docs/approved-walk-source/`；这是有保留的同意，不代表用户确认成品已精修完成。

精一步态改为按实际二维路程推进：`frames.playback.cycleDistanceDip` 默认每完整周期 84 DIP，路线会适配为整数个半步，尽量在接触姿势停下；按住鼠标、拖动、点击或被边界阻止时不会继续原地空转步态。左右移动按素材朝向镜像，停下或点击时保持朝向，切换形态后重置。

满屏移动改为短暂加速、稳定巡航和减速，`roaming.accelerationSeconds` 默认 0.28 秒，默认巡航约 95 DIP/秒，取消原先整段缓动造成的中途速度激增。精一的自主短走调整为 88–125 DIP、1.2–1.7 秒，权重、等待和冷却不变。其余三个人物仍使用旧动作与原有时钟播放，本轮未将精一图替代它们。

当前解决的是精一帧序接入、步频与距离脱节，以及路线速度变化。八帧 AI 素材仍存在衣装/姿态跳变，脚步有近似；没有实现持续精确的脚底锁定、真正多视角转身或手工精修动画。左向是现有素材的镜像，不是新增左向原画。

源码包先运行 **build.ps1**，构建后双击 **启动苹果乐.cmd**，或运行 **app/Applele.exe**。面向普通使用的 **Applele-Windows-x64.zip** 解压后直接双击其中的 **Applele.exe**。支持 Windows 10/11 x64，本版已自带 .NET 8.0.30 运行时，无需另行安装 .NET。保留整个解压目录；配置、素材和运行时文件都与程序一同交付。

## 操作

| 操作 | 行为 |
|---|---|
| 左键 | 随机 A/B 反应，含准备、表现、收尾；播放期间忽略重复点击 |
| 按住左键移动 | 拖动并中断自主动作，松手不误触反应 |
| 短按右键 | 精一 → 精二 → 异格精一 → 异格精二 → 精一；玩偶不参与循环 |
| 按住右键约半秒后松开 / Shift+右键 / 托盘右键 | 打开菜单：选择形态、返回玩偶、暂停/恢复、找回、开发状态、退出 |
| 菜单“开始满屏溜达 / 停止满屏溜达” | 持续向屏幕不同区域走动，途中短暂歇脚；停止后回到安静性格 |
| 菜单“走到屏幕另一处” | 主动走一趟，抵达后恢复待机 |
| 菜单“演示一次蹦跶 / 冲刺 / 抖动（调试）” | 玩偶主动预览对应特殊动作；四立绘未配置这些动作，因此禁用 |
| 菜单“开发状态 / 调试开关” | 当前状态、动作、下次决策时间、各行为等待/冷却和未触发原因 |
| 托盘双击 | 找回主屏幕右下边缘 |

“暂停自动走动”暂停自主行为和满屏溜达，手动反应和拖动仍然可用。左键点击、拖动或切换形态会取消当前路线；连续溜达模式保留意图，交互结束后休息一会再规划下一段。找回宠物也会取消旧路线并先歇脚，保留用户的暂停设置。菜单关闭会重新等待。每次启动默认显示玩偶。同时按左右键时优先完成先按下的那个手势，避免拖动被打断或误切形态。

## 满屏导航

原先只有短距离横向位移。现在位移包含 X/Y 两个方向，主动溜达会按随机顺序访问当前显示器的四个区域，路线穿过屏幕中部；不局限在底边。整个宠物画布留在工作区内，避开任务栏，不穿越显示器之间的空隙。小屏幕空间不足时安全待机。

普通启动保持安静性格。右键“开始满屏溜达”会启用连续探索；“停止满屏溜达”退出该模式；“走到屏幕另一处”只执行一段路线。这两个主动移动命令会恢复移动暂停状态。连续模式下的点击、拖拽或菜单会中断当前路线，结束后先等待 1.2–3 秒再继续。暂停/恢复保留溜达开关，退出并重启后默认回到安静模式。

导航参数在 **app/config/pet.json** 的 `roaming` 中：默认平均速度 95 DIP/秒、段间休息 1.2–3 秒、目标边缘留白 10 DIP、最长单段 45 秒。运动缓动使起止速度为零。修改源码配置 `config/pet.json` 并构建可更新发布配置。`ScreenNavigator` 只规划路线，状态机负责中断和恢复，桌面适配层负责 DPI、二维位移余数和工作区约束。

默认 `allowSpecialDuringRoaming: true`，连续溜达抵达并歇脚后，也可由同一个调度器低概率选择蹦跶、短冲刺或抖动，然后继续规划满屏路线。仅到达歇脚时参与决策，不在行进中抢控制权；普通短步行不参与这一决策。设为 `false` 可保持纯路线溜达。四立绘没有这些特殊行为，仍按各自克制的配置活动。

## 步态和动画来源

保留玩偶软体网格步态：两侧脚交替抬起，身体双拍起伏、倾斜、重心移动和落地压缩。移动使用起止速度为零的缓动；走动/反应 30 FPS，待机 15 FPS。自主短步行也可以上下或斜向活动。

**每周期 24 个步态姿势是程序网格变形缓存，不是画师绘制的帧，也不是参考图自带的动画。** `Gait.cs` 定义绑定与节奏，`PlushRigCache.cs` 在启动时从透明玩偶纹理生成缓存，不改写源 PNG。新版在相邻姿势之间做预乘 Alpha 平滑混合，待机与反应也不再直接跳换稀疏缓存帧。测试导出的诊断帧在 `docs/windows-stage4/procedural-walk/`。本版不声称还原原作机甲的完整步行动画。

点击是两张不同参考图配合程序分阶段过渡，蹦跶、短冲刺与抖动是程序动画。冲刺加快交替步频、增加倾斜和轻微弹性，抖动以衰减包络左右摇摆，结束回到原姿态，没有添加或重绘角色设计。切换在预乘 Alpha 中混合，避免独立动画争夺控制权或闪白黑底。拖动优先于自主动作，点击中断自主动作，重复点击不重启反应，取消仍消耗冷却。挂起后不补播积压动作、不瞬移。

原图仍完整保存在 `resources/originals/`，SHA256 清单保留。最初七张透明 PNG 放在 `resources/sprites/`，本次未覆盖或修改；它们由 imagegen 提取和修复细节，并非无损抠图，保留原图裁切范围。新的人物动作另存于 `resources/animations/`，补全了原图缺失的腿部、靴子。这些部分是 AI 推断，不能视为官方设定还原。旧提取提示词见 `docs/image-prompts.json`，来源见 `docs/asset-provenance.json`；新增动作来源与 SHA256 见 `docs/character-motion-assets.json`。

## 四种立绘

四种形态现在分别接入 **8 帧 AI 重绘走动关键姿势、两组各 4 帧的点击动作**。腿部、手臂和衣摆随姿势改变，走动由实际不同图像播放。点击按中立、准备、表现、收尾四帧播放；不在不同肢体姿势之间做叠影混合，避免重影。待机使用各形态的中立帧加程序呼吸和轻晃。引擎最高 30 FPS 不代表有 30 张独立绘制的动作帧。总计 64 个帧格含重复的中立姿势，不是 64 张完全不同的手绘图。

这是 AI 辅助重绘的轻量动作版本，包含外观和细节的近似，不是官方动作、精确原画分层或完整手工逐帧动画。腿部与靴子由裁切参考推断。八帧步态的衔接和细节一致性仍有提升空间，转身、多视角和更细致的脚部落地尚未提供。可补充画师动作帧替换对应图集；运行本版无需额外素材。

`config/pet.json` 的 `frames` 配置关联每个形态的动作图集、网格尺寸和帧序。`FrameAtlas` 验证真实透明边界并注册身体中心与脚底基线，不裁掉跨格的衣摆或武器；不规则间距通过完整透明间隔分格。异格步态分成两页各 4 帧。`PortraitRigCache` 只缓存当前形态，切换后释放旧资源，原始大图解码后立即释放。缓存准备期间暂停动画计时。设 `frames: null` 可显式回退到旧透明立绘的程序动画。

| 形态 | 点击 A / B | 日常节奏 |
|---|---|---|
| 精一 | 举手比耶 / 轻挥招呼 | 较亲近，偶尔短走，约 84 DIP 完整步态周期 |
| 精二 | 胸前致意 / 点头回应 | 更克制，持枪步行，0.92 秒步态周期 |
| 异格精一 | 举手比耶 / 衣摆轻扬 | 相对活泼，长衣摆摆动，0.78 秒步态周期 |
| 异格精二 | 从容点头 / 举手招呼 | 最安静，保留肩扛武器轮廓，1 秒步态周期 |

精一、精二和异格形态保持各自发色、服装配色、光环与主要装备轮廓，独立悬浮背景武器、爆炸等场景装饰未加入桌宠。完整生成提示词在 `docs/character-motion-prompts-v2.json` 和 `docs/character-motion-spacing-prompts.json`，使用内置 image_gen 工具生成并保留真实 Alpha，原始参考未覆盖。

## 性格配置

编辑 **app/config/behavior.json** 后退出并重启。源码配置在 **config/behavior.json**，构建时复制到 app。形态通过 `behaviorProfileId` 关联性格，后续立绘可使用独立配置。

每种行为分别配置 `weight`、`waitMin/Max`、`durationMin/Max`、`cooldownMin/Max`、`distanceMin/Max`、`allowedStates`。玩偶默认每 20–46 秒决策，待机权重 78、走路 20、蹦跶 1、冲刺 0.6、抖动 0.4；特殊动作总权重仍为 2。只有等待和冷却完成且当前状态允许的行为进入权重池。这些不是每帧概率或固定频率。

短步行约 30–78 DIP、持续 2.4–3.6 秒；蹦跶约 1.1–1.35 秒；冲刺约 70–135 DIP、持续 0.9–1.2 秒；抖动约 1.05–1.3 秒，不移动窗口。三种特殊动作均带启动冷却，各自冷却 180–420 秒，并共享结束或被中断后至少 150 秒的特殊动作间隔。调试演示会跳过自然触发门槛以便主动预览，结束或被中断时仍消耗冷却，不修改默认性格参数。

固定种子 903 的 24 小时安静模式模拟：约 98.58% 待机、391 次短步行、13 次蹦跶、9 次冲刺、9 次抖动。另有48小时边界与特殊动作间隔模拟通过。这些是模拟统计，不保证每次运行相同，也不等于实际运行了 24 或48小时。开发面板可调整大小并滚动，列出所有动作的等待与冷却，刷新时保留滚动位置。

## 架构与验证

Core 中的状态机、调度器和动画曲线不依赖桌面 API。Windows 项目分别维护 Windowing、Assets、Animation、Input、Movement、UI、App，未把功能集中回窗口类。

运行 `./build.ps1` 会测试、发布并启动窗口检查，需要 .NET 8 或更新 SDK；首次构建独立版会从官方 NuGet 源获取 Windows x64 运行时包。应用没有额外第三方库。构建前应退出正在使用 app 目录的实例。`-OutputDirectory` 可指定其他输出目录，`-FrameworkDependent` 可构建依赖系统 .NET 的开发版本。运行时许可证和第三方声明在发布目录 `licenses/`。

本次 **70 项逻辑测试、234 项窗口检查、4 项故障退出检查**通过，记录在 `docs/core-walk-playback.json`、`docs/windows-walk-playback/windows-character-frames.json` 与 `docs/release-failure-checks.json`。包含原有交互和导航回归、冲刺与抖动的真实窗口表现、双键输入与捕获丢失、找回后的路线取消、调试面板滚动，以及缓存平滑、计时隔离、200% 缩放透明边界和资源释放。故障检查脚本现已纳入 `tests/ReleaseChecks.ps1`，默认构建会运行它。诊断帧与浅深底边缘检查图在 `docs/windows-walk-playback/`。100/125/150/200% 渲染表面检查不等同于实体多屏测试。既有 70 项人物动作检查覆盖透明分格、脚底与身体注册、8 帧下肢图像变化、点击互斥与恢复；导出的实际渲染帧在 docs/windows-walk-playback/character-frames/。可用 Applele.exe --check-art --report <目录> 单独运行人物资源检查；Applele.exe --check-walk --report <目录> 可单独运行本轮新增的 11 项走动窗口检查。

检查时屏蔽系统 .NET 根目录，确认实际加载的是发布目录的 `coreclr.dll`，同时发布配置使用 `includedFrameworks`；未在没有 .NET 的干净虚拟机上另做测试。本轮五秒玩偶待机采样约 139 MiB 工作集，GDI 句柄保持 28；这含检查过程建立的额外测试画布，不能代替长期运行指标。逐形态原始采样见 `docs/windows-walk-playback/polish/portrait-performance.json`。

自动窗口检查运行在 Codex 隔离桌面。用户 Default 桌面的更新和形态切换另记录在 `docs/user-desktop-walk-playback.json`；此前记录也保留。这不等于用户已人工确认本次所有画面效果。

本轮补齐了四形态的 AI 动作关键帧和独立包；多角度动作、画师精修和更精细的步态仍需要后续美术资源。混合 DPI 多屏、远程桌面与长期运行仍需硬件人工验收，当前版本未做数字签名。
